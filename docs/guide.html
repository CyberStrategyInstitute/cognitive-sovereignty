1. Understand the model

The six domains describe human capacities. The five causal layers connect conditions, techniques, delivery, and outcomes. CTSS ranks an assessed risk using likelihood, agency impact, reach, detection difficulty, and recovery difficulty.

Learning hub · Threat explorer · Detailed framework reference

2. Assess one item

Save the source and dates. Identify the mechanism and affected people. Explain U.S. relevance and the existing taxonomy links. Assign five estimates with reasons. Use a provisional label where assumptions remain. State what evidence would change the score.

The total is L×5 + Ia×6 + R×4 + D×3 + RecD×2. This is the unchanged weighted formula written as whole points. A score is our assessment, not proof that the source measured human harm.

3. Track the next action

The signal register separates documented guidance, research questions, watch items, deferred scoring changes, and grouping labels. Each entry has a stable ID, responsible role, review trigger, and history. Closure needs evidence. A responsible role is not a named assignment.

Search the register · Recommendation coverage and remaining work

Apply controls and test capability

The controls and readiness page connects all six domains with the shared mitigation catalog, assessment resources, and roadmap. Follow the worked unit example, then use the worksheet to retain evidence and failures. Capability scores, event CTSS, and self-report remain separate.

Domain tables and the full catalog are generated from resources/controls.json and resources/domains.json. The same records feed the webpages and read-only agent/MCP queries. Source evidence remains distinct from an implementation result.

4. Rebuild and check

Canonical records live in the taxonomy, research intake, and lens folders. The Python tools calculate scores, preserve assessment revisions, generate reports, and export the website data. The browser does not maintain a second score database.

python -m tools.build rebuilds the views. python -m unittest discover -s tests checks behavior. GitHub checks also verify exports, links, scripts, and the optional MCP adapter. No automatic merge or release is configured.

Contribution guide · Changes

5. Use it from an agent or MCP server

Start with the versioned data catalog. It names canonical files, schemas, method, baseline, counts, and hashes. Use stable IDs and preserve the assessment date, provisional status, sources, and lens.

The local query command returns bounded JSON results. An optional read-only MCP adapter exposes the same collections and CTSS calculation over local standard input/output. It cannot edit records, publish content, fetch arbitrary URLs, or read arbitrary paths. It is an integration example, not a deployed authenticated service.
